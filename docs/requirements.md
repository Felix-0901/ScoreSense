# 樂譜辨識與自動標註系統需求與課程對照

## 文件目的與現況界線

本文件將「樂譜辨識與自動標註系統」自主學習課程說明，對照目前程式碼可確認的功能。它記錄產品需求、實作範圍與待驗證項目；**不代表任何章節的教學、學生理解、測試或成果整理已完成**。

核心目標是讓使用者提供樂譜圖片或既有 MusicXML 後，取得加上 Do Re Mi、數字或注音唱名的 MusicXML 樂譜。課程採章節式、成果導向，並不以固定堂數作為完成判定。

## 目前需求

1. 接受 PNG、JPG、WebP、BMP、TIFF 等樂譜圖片，或 XML、MusicXML、MXL 樂譜檔。
2. 圖片輸入可先進行灰階化、局部對比增強、有限度傾斜校正與二值化預覽，再交由選配的 oemer OMR 轉為 MusicXML。
3. MusicXML／MXL 輸入須讀取有音高的音符，略過休止符，取得音名、升降記號與八度資訊。
4. 使用者可選擇 `solfege`（Do Re Mi）、`numbered`（1–7）或 `zhuyin`（注音）標註；可選擇是否顯示升降記號與簡單八度箭頭。
5. 系統須把標註寫入 MusicXML 的 lyric line `99`，保留其他歌詞行；原有第 99 號歌詞行會被替換；重跑時只取代該行標註，並輸出 `notes.json`。
6. 提供本機 CLI 與 FastAPI 網頁介面：上傳檔案、選擇模式、取得處理結果、用 OpenSheetMusicDisplay 顯示並下載 MusicXML。

## 明確限制與未實作範圍

- 目前轉換採**固定 Do**：C→Do／1／ㄉㄛ，D→Re／2／ㄖㄟ，依此類推；數字為固定 C 大調音名對照，**不是首調唱名，也不是包含調性、節奏、時值、連線與排版規則的完整簡譜**。
- 程式以 `xml.etree.ElementTree` 直接讀寫 MusicXML；課程規劃中的 `music21` 目前**未使用**。因此調號、拍號、小節語意與首調推導均未由現行程式分析。
- PDF、圖片成品輸出、多頁樂譜處理、列印與 MuseScore 匯出未實作。
- 沒有 Flutter 專案、手機相機或相簿流程；FastAPI 僅提供本機網頁/API，不能視為手機 App 完成。
- 圖片辨識依賴選配的 `oemer` 與其模型；沒有 oemer 時仍可處理既有 MusicXML。OMR 對不同樂譜、照片品質與辨識準確率尚未在本文件工作中驗證。

## 驗收基準

核心展示須以可重現的實際證據確認：

1. 以 `samples/twinkle.musicxml` 或另一份可公開使用的 MusicXML，成功產生三種任一指定模式的標註檔與 `notes.json`。
2. 輸出的 MusicXML 保留非第 99 號原有 lyric，且僅有標註 lyric line `99` 被新增或更新。
3. 在可用 oemer 的環境，以至少一張樂譜圖片完成前處理、OMR、標註與顯示；須另外記錄輸入條件與實際辨識結果。
4. 若要宣稱核心課程成品完成，需另完成不同圖片條件的測試紀錄與學生的系統／問題／改善說明；App、PDF 與首調唱名為後續延伸，並非目前核心驗收前提。
