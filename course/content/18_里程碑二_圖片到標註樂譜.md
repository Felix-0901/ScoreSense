## 二、建立教學版主程式

```python
from pathlib import Path

from image_preprocessor import preprocess_score
from omr_runner import run_oemer
from musicxml_tools import annotate_musicxml


input_image = Path("materials/score_clean.png")
work_dir = Path("output/milestone2/work")
result_dir = Path("output/milestone2/result")

work_dir.mkdir(parents=True, exist_ok=True)
result_dir.mkdir(parents=True, exist_ok=True)

print("[1/3] 圖片前處理")
pre = preprocess_score(input_image, work_dir / "preprocess")

print("[2/3] OMR")
omr = run_oemer(pre.enhanced_path, work_dir / "omr")

print("[3/3] 自動標註")
notes = annotate_musicxml(
    omr.musicxml_path,
    result_dir / "annotated_zhuyin.musicxml",
    "zhuyin",
)

print("完成，音符數量：", len(notes))
```

## 三、如果第 2 步壞掉，應該查哪裡？

不要直接改第 3 步。

檢查順序：

```text
preprocessed.png 是否正常？
↓
oemer.log 寫了什麼？
↓
有沒有產生 MusicXML？
↓
MusicXML 能不能人工打開？
```

如果 MusicXML 本身錯，後面標註器再正確也救不了原始辨識。

## 四、建立「不用 OMR」的旁路測試

同時保留：

```python
annotate_musicxml(
    "materials/twinkle.musicxml",
    "output/direct_test.musicxml",
    "solfege",
)
```

這樣當 OMR 環境壞掉時，仍可快速確認後半段系統是否正常。

這叫做**隔離問題**。

## 五、比較是否開啟前處理

執行兩組：

### A

```text

```

### B

```text

```

注意：前處理不是保證一定變好。如果某類樂譜反而變差，也是一個有效實驗結果。
